# Sprints

Each file in this directory is a sprint log: what was scoped, what was
actually built, what was deferred, and the decisions worth remembering.

Format: `NN-short-title.md`. One sprint per file. Don't rewrite history when
priorities change — open a new sprint.

- [13-deletions-and-user-channel.md](13-deletions-and-user-channel.md) — Destructive flows (task / project / workspace delete with shared `ConfirmDelete` + type-to-confirm); sync hygiene (server-rejected ops block the queue with a recoverable retry/discard popover, drained-queue auto-`hydrate()`); a dedicated per-user WS channel for events that decide *who* can subscribe to the workspace feed — fixes a chicken-and-egg where a new member never received the op that added them.
- [14-account-linking-and-personal-overlay.md](14-account-linking-and-personal-overlay.md) — Two opt-in read-only overlays so a person sees one timeline: account linking (type a partner's email, paired identity chip in the topbar, mutual calendar visibility) and personal-workspace overlay (project your personal blocks onto a team workspace). Sticky receive-side modal driven from the persisted row so it survives refresh. Fixed an infinite-loop selector that returned fresh array literals.
- [15-project-roles-and-mobile-polish.md](15-project-roles-and-mobile-polish.md) — Per-project role grew to {`owner`, `lead`, `member`, `inactive`} with passive roles hidden from inbox assignee groups; inbox gets an Unassigned bucket and `setTaskAssignee(null)` auto-flips Now → Later; calendar rail sorts by inbox order; first round of mobile polish (`<Select>` opens on iOS, scroll fixes, ghost scrollbar gone).
- [16-mobile-touch-drag.md](16-mobile-touch-drag.md) — Touch drag end-to-end via the hybrid pattern: pointer events for state, document-level non-passive `touchmove` for `preventDefault`-suppressed scroll. 220 ms long-press anywhere on a row, plus the explicit `::` grip. Calendar block tap-to-reveal-then-tap-to-open. iOS preventDefault-mid-gesture turned out to need touch events specifically, not pointer events — that took most of the sprint to land.
- [17-mobile-layout.md](17-mobile-layout.md) — Real mobile layout (not "desktop, made tappable"): 3-day calendar centered on today with single-day prev/next, slide-over sidebar with hamburger, topbar pruned to breadcrumb + sync pill + Log out, inbox row stripped to grip · check · title, task rail stacked under the calendar on phones. Independent `dayOffset` cursor so desktop and mobile don't fight when you switch.
- [18-mobile-touch-mk2.md](18-mobile-touch-mk2.md) — Mobile layout met touch reality. Dynamic viewport (`100dvh`) so the inbox / calendar / modal stop hiding under Safari toolbars. Long-press visual fires *only* at lock — earlier flash made quick taps look like rejected gestures. Two-tap grace window for time-block action buttons so the first tap can't accidentally fire X / tick / duplicate. Big debug saga that ended with a structural fix: the inbox grip's parallel pointer handlers were silently intercepting touches and bypassing the long-press hook entirely. Drag paths now split cleanly by input type — Desktop = HTML5, Mobile = long-press, single path. Plus PWA install (icons, manifest, safe-area insets) and the new shared `useLongPress` hook.
- [19-email-invites.md](19-email-invites.md) — Email-based workspace invites replace the global user-search picker, which was an onboarding wall for anyone not already in the system. Owner enters an email, recipient gets a sticky modal mirroring the account-link receive UX, accept switches them straight into the just-joined workspace. Membership editing is now one-mutation-per-click — Save Changes is title-only, role changes fire immediately, removal is a typed-email confirm hitting a dedicated `DELETE` endpoint that cascades the soft-delete into project memberships. Tasks and time blocks owned by ex-members stay (it's history, not stale data). Plus the iCloud "Hide My Email" QuickType chip finally went away after switching the inbox add-task field from `<input>` to `<textarea rows={1}>` — the heuristic is keyed off the element type, nothing else worked.
- [20-time-block-polish.md](20-time-block-polish.md) — Time-block action row scales with `--fs-scale` (Lucide icons sized via a CSS class, not the prop) and collapses to a kebab + above-block popup on short / overlapping blocks. Touch finally separates "single-press scrolls" from "long-press drags" via `touch-action: pan-y` + an always-on `touchmove` listener that branches on a freeze flag set at long-press lock. Tap activation deferred to release so a swipe-to-scroll doesn't highlight every block it passes. Task modal grows full block CRUD: click-to-edit date / start / end (duration is read-only computed); trash button to delete; "+ Add block" creates a 1 h block ending at the next 15-min boundary; end-time `00:00` is the special-case "end-of-day" save (next day's 00:00). Plus: real-time clock + today highlight via a 60-s `setClockTick`, modal backdrop close gated on mousedown-AND-click both landing on the backdrop (so text-selection drag-out doesn't dismiss), Enter-on-subtask creates the next subtask via a new `addSubtask(taskId, title, afterId?)` path with a real fractional-indexing midpoint sort_key. Plus the SQL recipe for moving a project across workspaces.
- [21-tags.md](21-tags.md) — Tags grow up: per-project entity with UUID identity, color, edit/rename/recolor/delete in `ProjectModal`, multi-select picker on the task modal, sticky AND/OR filter strip on the inbox. Five new ops (`tag.create`, `tag.set_title`, `tag.set_color`, `tag.delete`, `task.set_tags`); `tasks.tags TEXT[]` dropped, `task_tags` join table replaces it; `task.create.tag_ids` replaces `task.create.tags`. Filter persists through `partialize`, prunes phantoms on bootstrap and on `tag.delete`, auto-attaches the active filter to quick-add tasks so they don't immediately disappear from the row they were typed into. Inbox row trail caps at 3 chips (1 on phones) + `+N` overflow, sorted match-first under an active filter and length-desc inside the filter strip itself. Faint color-mix outline replaces the colored dot. Mobile places the Tags editor in the main pane (sidebar is closed by default on phones). `--done` desaturated from Tailwind green-700 to a muted sage so the ticked time block stops shouting.
- [22-task-attribution-and-account-settings.md](22-task-attribution-and-account-settings.md) — `tasks.created_by` (server-stamped from the actor) and `tasks.finished_at` (server-managed via the existing `task.tick` / `task.set_status` ops) plug two information holes; modal shows the creator, inbox Done sorts newest-finished-first with a `created_at` fallback for legacy rows. Topbar's two-avatar + link cluster collapses behind a single avatar that opens a new `AccountSettingsModal` (identity card, link affordance with state-aware copy, stubbed gcal Connect, personal/work mode badge, Log out). Settings persist server-side via a new `user_settings` table + `PATCH /api/me/settings` with tri-state `Option<Option<T>>` for "absent vs explicit null"; `Bootstrap.settings` ships them at boot. Compact mode badge sits flush against the avatar via a `topbar-account` flex wrapper (parent's `gap: 12px` was beating the margin tweaks). Inbox gains a `me/all` scope toggle in the filter strip, collapsing the Now assignee groups to just the caller when `me` is on. Section picker in the task modal swapped for a colored pill matching `StatusEditor` (factored to a shared `TonedPicker`), with the popover portaled to `document.body` so it escapes the modal sidebar's `overflow: auto`.
- [23-gcal-events-base.md](23-gcal-events-base.md) — Real Google Calendar ingest, end-to-end. Separate incremental-authorization OAuth flow (`/api/gcal/connect` → `calendar.readonly` with `access_type=offline` + `prompt=consent`, the second being non-negotiable to actually receive a refresh_token). New `gcal_credentials` table for server-managed tokens (kept apart from `user_settings` since lifecycles differ); `gcal_events` extended with `description`, `google_event_id`, `html_link`, `updated_at_remote`, with a partial unique index `(user_id, google_event_id)` for idempotent upsert. `sync_user_calendar` refreshes the access token, fetches events in a −2w/+8w window, upserts, and deletes anything that fell off Google's end. Hooked into bootstrap as fire-and-forget so Google latency stays off the critical path; the OAuth callback runs an inline sync so first connect lands events synchronously. Connect button in `AccountSettingsModal` becomes a real link (with Disconnect + connected email when set); `.gcal-evt` becomes clickable for own events and opens a portaled popover with title, time range, description, and an "Open in Google Calendar" link. All-day events, multi-calendar, and `syncToken` incremental sync deliberately deferred.
- [26-account-switcher.md](26-account-switcher.md) — Fast switch between linked accounts without going through Google again. New `sessions.session_group_id` + `sg` cookie binds sessions to the same browser; switching is gated on both the link relationship (DB) AND a live sibling session in the group (cookie). `Switch to {Personal | Work | name}` button next to the Linked-account row in `AccountSettingsModal`, "Add another account" affordance to bootstrap two-in-group, "Sign out everywhere" for the full clear. Per-account `localStorage[fira:lastView:{userId}]` snapshot (workspace + view + project) so a switch lands the user where they were instead of their personal-workspace inbox. `sg` is HttpOnly + Lax + Secure, and every endpoint that reads it (`/auth/accounts`, `/auth/switch`, `/auth/sign-out-everywhere`) also requires a valid `AuthUser`; sign-out-everywhere narrows the DELETE to caller + linked partners so a stranger inheriting an `sg` cookie on a public device can't kick prior users.
- [27-stress-testing.md](27-stress-testing.md) — Built a load harness (`stress_seed` bulk-COPY seeder, `stress_load` concurrent driver, `dev-stress-api.sh`) against a separate `fira_stress` DB and drove it to 1,000 concurrent users. Headline bug: `load_bootstrap`'s 12-way `tokio::try_join!` over `&PgPool` grabbed 12 pool connections per call — ~8 concurrent bootstraps exhausted the pool and 46% failed; fixed by running the hydrate queries sequentially. Three client findings: the `persist` middleware blows the ~5MB `localStorage` quota above ~8k tasks/workspace; WS nudges weren't debounced/coalesced so a workspace under write load fetch-stormed every connected browser; `applyRemoteOp` stored raw partial create payloads, leaving tasks with no `sort_key` that crashed `<InboxView>`. Dataset right-sized to a medium profile (50 ws × 3 proj × 2k tasks); final run holds 1,336 req/s at 0 errors. Bounded-bootstrap (the real scaling fix), op-apply backpressure, IndexedDB persistence, and `/ops` rate limiting deferred.
- [28-jira-integration.md](28-jira-integration.md) — Full write-path Jira integration in one sprint: connect (per-user API token, per-workspace site — `workspaces.jira_site_url` + `jira_credentials(user_id, workspace_id)`, after reversing out of both a shared-token and an account-wide-token design), create issue from task (`projects.jira_project_key`, pushes into the existing manual issue-link fields via two synthesized ops, epic picker in its own modal per direct feedback against an inline first draft), and worklog push (`time_blocks.jira_worklog_id`/`jira_sync_error`, authenticated as the block *owner* not the actor, manual first push + automatic fire-and-forget resync on further edits). Also fixed two real bugs hit in testing: Jira's deprecated `/rest/api/3/search` (410 Gone — swapped to `/rest/api/3/search/jql`) and a modal missing padding (`.np-actions` needs to nest inside `.np-body`, not sit beside it). Write-only by design — status mapping, content sync, and pull-from-Jira are explicitly out of scope.
- [31-plan-view.md](31-plan-view.md) — Fourth surface: a project roadmap board with weeks across, tracks down, and sprint cards holding real tasks. The model took three attempts — tracks-as-tags died on "many tasks have multiple tracks at the same time" (`task_tags` is M:N, so a task renders twice and the `3/4` counters double-count), and what landed is the single-valued chain `task.sprint_id → sprint.track_id → track`, which needs *no validation rule* because nothing can render twice. `epics` renamed to `tracks` rather than adding a table (it inherits the FK, bootstrap field, store array and move-impact handling; "epic" is spoken for by Jira's). Eleven narrow per-field ops after finding four distinct op shapes already in the codebase and reasoning out which fits a nullable `track_id` edited by drag. Biggest detour and biggest payoff: **the seeder became an op script** — content now replays through `apply_payload` with backdated `applied_at`, so a reseed exercises every content op handler (165 ops, 13 weeks) and the dev DB finally has history to scrub; acceptance test was a `jq`-normalised `dump-bootstrap` diff that came back identical. 26 backend tests (17 pure `project_at` + 9 `#[sqlx::test]`, which works out of the box), 21 psql assertions on the rename over populated data, ~60 in-page dev assertions for the wrong-by-default algorithms (ISO week at year boundaries, local-midnight date keys, DST-safe week deltas, lane packing). Retro band reconstructs the past from completed-block spans → `finished_at` → `created_at`, derived not materialized, drawn dashed and outside every track because a record is not a plan. Projection lives in Rust, reversing an earlier call — the client doesn't have the op log. Sidebar entry gated out of production builds: `processed_ops` is never pruned, so an op shape that reaches a real user is permanent, and the UX isn't settled. Everything was green — typecheck, build, 26 backend tests, ~60 in-page assertions — while the board was unusable, and the bugs only fell out of rendering it and driving the gestures: a `position: relative` silently overriding `position: sticky`; an axis spacer that didn't stick, so week labels drifted out of register; a default window opening on empty weeks; an inbox predicate built on the plan's wrong belief that `task.tick` moves a task's section; and worst, **card move and resize doing nothing at all** because the card was both an HTML5 drag source and a pointer-drag handle — `dragstart` fires on the first pointermove and kills the pointer stream. Collapsed to one pointer gesture carrying week span and track row together, the way the calendar's block drag carries time and day. Sprint creation became a toolbar button that arms the grid for a crosshair sweep across weeks, and the cyan accent was stripped in favour of track colour against paper. A second pass — someone *looking* at the result rather than driving it — found a different class of fault again, mostly the board saying things twice or in its own private language: a `3/4` counter sitting directly under the checklist it restated, a track-coloured ring meaning "today is inside this span" on a board where a card's position already says that, and a now marker so quiet it lost among twenty-six identical week labels (now the calendar's current-day marker, token for token — the one place `--accent` belongs here, because a week board and a day board disagreeing about where "now" is would be indefensible). Inline card-title editing turned out to be unfixable rather than buggy: the header is the move handle and the title fills it, so the title either swallows `pointerdown` and the card can't be dragged, or it doesn't and every short drag opens an edit box — rename is a pencil button now. Checklist rows gained drag-reorder (driving the list's own section-scoped `reorderTasks`, not a board-local order) and click-to-open, which exposed a hazard: ordering is section-scoped, so a cross-section drop moves the task's section, and across the *done* boundary that silently un-archives finished work — fixed by sinking finished rows out of the ordering entirely, which also repaired a ticked-but-not-archived task sorting to the top of its own card. The retro band was incoherent and one clause fixed it: it bucketed *every* finished task, including the ones already rendered in cards one row above — the exact double-render the single-valued membership model exists to prevent — and so had no rule by which anything ever left it; scoped to `sprint_id === null` it means "finished work that was never planned", which gives it a self-clearing rule, two ways out (drag a row onto a card, or Promote the whole fortnight into a real sprint), and an answer to "what if we keep working without sprints?". That fix then exposed a hole in the fixture — the seeded board had *zero* unplanned finished tasks, so the corrected band was empty everywhere. The rail stopped being a second-rate reimplementation and borrowed properly: the calendar's frame, the list's section heads (all four, always counted), and the list's `ListTagFilter` extracted and shared in place of a hand-rolled chip panel — then the borrowing went one step too far and had to come back, because a calendar rail row answers *how big is this* across two lines and 44px while a plan board asks only *where does this go*. Rows are one line of title now, and the real fix was making the rhythm explicit: `--plan-task-h`/`--plan-task-fs` are **one task line**, used by a card's checklist, its add-task row, the Past band and the rail alike. They had been four independent sets of paddings and font sizes — an 18px `--fs-xs` sliver beside a 44px two-line row, for the same object, on the same screen — because they live in different components and nothing forces them into one frame except the screen, which does it constantly. Modern then came out a size too big because `--density` was multiplying whole rows rather than the padding its own definition describes (a task row at 31.9px against classic's 22px: not 30% roomier, a size and a half) and panel widths too (a 319px rail while the week columns, a JS constant, didn't move) — rows are line-box-plus-padding now and panel widths are fixed per style, as `--side-w` already is. Axis labels were set *larger* than the content they label, 15.8px of chrome over 13.8px of task text; they're 10px-scaled now, week numbers in tabular mono, and the axis lost 11px without folding its two rows, which the rail's filter box rules out anyway since the two headers have to close on the same line. Plus a dead 15px band between rail and board that turned out to be `scrollbar-gutter: stable` inherited from the calendar, where it's deliberate (rows subtract `--scrollbar-w` to match) and here bought nothing; axis rules that began in mid-air until the month strip got a rule for them to start from; and a toolbar that was right about the idiom and wrong about the number — it now inherits the calendar's flat 22px segment and measures identically to the calendar bar. A reported font mismatch between the Track/Sprint and Inbox/Tasks segments turned out, on measurement, to be identical type with different icon weights and ink — worth measuring before agreeing as well as before disagreeing. Navigation got fixed on the way: clicking a project in the sidebar used to force the list view, and now scopes whichever view you're in (plan, dashboard, list, or the calendar via its own solo filter), with the project highlight reading that view's cursor — on the calendar only when exactly one project is visible, which is the only time it isn't lying. Nav order is Calendar · List · Plan · Dashboard, widening over the same tasks with the roll-up last. Plus a horizontal line that slid during scroll, measured rather than guessed: `.plan-axis` took the scroll container's visible 989px while its children overflowed to 1844px, so its rule stopped partway and stayed pinned to the viewport. Scrubber (`/api/plan/at`, timeline strip, drift overlay) is sprint 32.
